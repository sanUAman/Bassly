# ADR 0002 — Layered Architecture for TicketWave (api / service / domain)

**Дата:** 2025-12-11  
**Статус:** Пропоновано / Приймається

## 1. Мета
Зафіксувати мінімальні правила шарів у модульному моноліті: що зберігається у `api/`, `service/`, `domain/`, напрямок залежностей та заборонені зв'язки.

## 2. Правила шарів

### a) api/
- Містить контролери (views), маршрути (urls) і DTO/serializers.
- Приймає HTTP-запити, викликає сервіси й повертає відповіді згідно контракту (OpenAPI).
- Не містить бізнес-логіки (виняток: мінімальна трансформація/мапінг DTO ↔ domain).

### b) service/
- Містить use-cases (функції/класи для виконання бізнес-операцій).
- Відповідає за валідацію бізнес-правил, транзакційність, координацію доменних обʼєктів.
- Сюди потрапляють всі інтеракції з domain-моделями (ORM), third-party adapters (payment, notifications), і кешування.
- Повертає доменні обʼєкти або DTO, але не формує HTTP-відповідей.

### c) domain/
- Сутності (Django models) та інваріанти (методи, які підтримують консистентність).
- Не повинно бути знань про HTTP, API або представлення.
- Повинні бути інваріанти, бізнес-правила рівня об'єкта (наприклад `Event.sell_ticket()`).

## 3. Напрямок залежностей
- `api/` → `service/` → `domain/`  
  (тобто верхній шар залежить від нижнього, але не навпаки)

## 4. Заборонені зв'язки
- `api/` **не має** звертатися напряму в БД (через domain) — все через `service/`.
- `domain/` **не має** містити логіку, яка залежить від `api/` або від зовнішніх сервісів (payments, web).
- `service/` не повинно залежати від деталей transport-layer (HTTP) — тільки інтерфейси/репозиторії.

## 5. Поради щодо організації коду
- Кожен bounded context (events, tickets, orders, auth) має власний набір `api/`, `service/`, `domain/` файлів.
- Внутрішні функції `service/` повинні бути простими для тестування (без HTTP).
- Використовувати транзакції у `service/` при зміні кількох сутностей одночасно.

## 6. Приклади
- `events/api/views.py` викликає `events/service.create_event()`.
- `events/service.create_event()` створює `Event` (domain) і повертає його.
- `Event.sell_ticket()` — доменна інваріанта, змінює `sold_tickets` у моделі.
