# Roadmap — Bbassly

## Загальний план розвитку на найближчі 4 тижні
Мета — створити працюючий базовий прототип системи продажу квитків: клієнтська частина, бекенд-API, база даних і мінімальні функції бронювання.

---

## Тиждень 1 — Базовий клієнт → бекенд → база даних
- Підняти сервер (Django).
- Створити базовий endpoint `GET /events`.
- Підключити SQLite/PostgreSQL.
- Створити таблицю `events` з тестовими записами.
- Зробити HTML-сторінку з кнопкою “Load places”.

---

## Тиждень 2 — Бізнес-документ, базова архітектура
- Створити `docs/business_doc.md`.
- Додати архітектурну діаграму та пояснення блоків.
- Додати `docs/roadmap.md`.
- Налаштувати репозиторій та роботу з fork → PR.

---

## Тиждень 3 — Розширення API + нові можливості
- Додати endpoint `GET /events/{id}`.
- Реалізувати модуль авторизації (мінімальний).
- Додати модель `tickets`.
- Реалізувати бронювання: `POST /tickets/book`.

---

## Тиждень 4 — Бронювання + CRUD + стабілізація
- Повноцінний CRUD для подій (організатор).
- CRUD для квитків (внутрішній бекенд).
- Додати `GET /health`.
- Підготувати схему OpenAPI для основних endpoint.
- Провести тестування та рефакторинг архітектури.

---

## Подальші плани (не обов’язково для цієї практичної)
- Додати реальний модуль оплати (LiqPay/Stripe).
- Додати модуль нотифікацій.
- Додати аналітику продажів.
- Підготувати мікросервісну структуру (за потреби).
